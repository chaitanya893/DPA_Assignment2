# Building the gold set (PDF: "Build a gold set")

The earlier `config/gold_set_300.json` was generated by a script (identical amounts every month,
identical ex-dates across funds, only `DECLARED` rows, 2024 only) and contradicted the project's own
schedule files, so it was removed. A gold set has to be verified by a person.

## Target

- **300 DECLARED events** across **at least 50 funds**, spanning **at least 24 months**.
- **Plus NOT_DECLARED rows**: months in which a fund paid nothing (without them precision
  cannot be measured).
- Primary sources only: the fund company's own distribution page / press release / PDF schedule,
  or the SEC / TMX filing. Never a market-data site.

## File: `config/gold_set.csv`

| Column | Meaning |
|---|---|
| `gold_id` | unique id, e.g. `g0001` |
| `fund_id` | id from `config/universe_100.json` |
| `window_start`, `window_end` | the window the detector will be asked about (usually one calendar month) |
| `expected_status` | `DECLARED` or `NOT_DECLARED` |
| `ex_date`, `gross_amount` | for DECLARED rows: the ex-date and total per share exactly as published |
| `currency` | `USD` or `CAD` |
| `evidence_url` | link to the primary source you checked |
| `verified_by`, `verified_at` | who checked it and when (YYYY-MM-DD) |
| `notes` | optional |

## Commands

```bash
python -m src.validators.gold_set_evaluator --validate-only   # checks size, funds, months, negatives, evidence
python -m src.validators.gold_set_evaluator                   # recall / precision / extraction accuracy
```

The evaluator runs the real detector with live sources. It never feeds the gold set to the detector.
Results go to `quality/gold_set_evaluation.json` and are picked up by `python -m src.reports.detection_report`.

## Tips

- Pick 50 funds across families and both countries; include the 10+ ETFs and 10+ monthly payers.
- For each fund, record every distribution in the 24 months, then add 2-3 months with no distribution.
- Copy the amount exactly as printed (do not round).
